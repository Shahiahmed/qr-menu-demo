## ⚠️ 403 в админке на проде — нужен `FilamentUser`

Filament в `APP_ENV=production` пускает в панель **только** модель, реализующую
контракт `Filament\Models\Contracts\FilamentUser` (метод `canAccessPanel`).
Локально/по IP:8083 (другое окружение) пускало и без него, а на домене с
`APP_ENV=production` вход после верного пароля отдавал **403 Forbidden**.
Починено: `User implements FilamentUser`, `canAccessPanel()` возвращает `true`
(одноклиентский сайт — любой вошедший = владелец). Не удалять этот метод.

## ⚠️ git-деплой как root: dubious ownership + exec-бит

- `deploy.sh` в конце `chown -R www-data`, поэтому следующий `git` под root
  ругается `dubious ownership`. Один раз выполнено на сервере:
  `git config --global --add safe.directory /var/www/qr-demo`.
- Exec-бит `deploy.sh` закреплён в git (mode 100755) — иначе `git reset --hard`
  восстанавливал 644 и `./deploy.sh` падал с `Permission denied`.

## Как устроен git-деплой

GitHub тут не используется (у основного проекта — `github.com/Shahiahmed/qr-back`,
но для demo отдельный репозиторий не заводили). Схема — **bare-репозиторий на
самом сервере**:

- Локально в `demo/` — обычный git-репозиторий, remote `server` →
  `ssh://root@185.194.217.14/var/www/qr-demo.git`.
- `/var/www/qr-demo` — рабочая копия, клон этого bare-репозитория.

### Обновление кода

Локально (из папки `demo/`, **PowerShell** — из-за кириллицы в имени
пользователя нужен именно Windows-ssh):

```powershell
$env:GIT_SSH_COMMAND = 'C:/WINDOWS/System32/OpenSSH/ssh.exe -i C:/Users/Ахмет/.ssh/id_ed25519'
git push server main
```

Затем на сервере:

```bash
ssh root@185.194.217.14 "cd /var/www/qr-demo && ./deploy.sh"
```

`deploy.sh` делает `git fetch/reset --hard origin/main`, `composer install`,
`migrate --force`, `storage:link`, `filament:assets`, кэши, права,
`reload php8.3-fpm`.

## ⚠️ На сервере НЕТ Node — ассеты Vite коммитятся в репозиторий

`npm`/`node` на сервере не установлены, поэтому `public/build` **принудительно
добавлен в git** (`git add -f public/build`) и приезжает вместе с кодом. При
изменении фронта — пересобрать локально и закоммитить:

```bash
cd demo && npm run build && git add -f public/build && git commit -m "rebuild assets"
```

## ⚠️ Кириллица в имени пользователя ломает git-bash ssh

`ssh` из Git Bash не находит `~/.ssh` (путь `C:\Users\Ахмет` манглится в
кракозябры). Использовать **Windows-ssh** (`C:\WINDOWS\System32\OpenSSH\ssh.exe`)
через PowerShell, либо `GIT_SSH_COMMAND` с прямыми слэшами (см. выше).

## Соседи не тронуты

Отдельные БД (`qr_demo`), отдельный порт (8083), отдельный nginx-блок, отдельный
каталог. Общий только пул `php8.3-fpm` (как у всех проектов на этом сервере —
`reload` на деплое кратко сбрасывает opcache соседям, принятая практика).
Проверено после деплоя: 8080 → 302, 8082 → 200, phytobiotech 443 → 200.

## SEO / OG — редактируется в админке (2026-09-01)

Всё SEO и OG теперь правится в `/admin` → **«Заведение» → вкладка «SEO»**:
двуязычные Title / Description / Ключевые слова (RU + KK) и **OG-картинка**
для превью при отправке ссылки. Хранится в `venue_settings` (синглтон id=1),
рендерится в `<head>` серверным Blade (`layouts/guest.blade.php`) через
хелперы модели `VenueSetting` (`seoTitle/seoDescription/seoKeywords/ogImageUrl`),
локаль-зависимо по `default_locale`, с откатами (пусто → название/описание;
OG-картинка пусто → обложка → дефолтное фото). Главная берёт дефолты из layout;
страницы блюд (`/d/{slug}`) держат свои Title/OG + JSON-LD и наследуют
ключевые слова заведения.

Дефолтные значения (RU+KK) для «Дастархан» **уже залиты** миграцией
`2026_09_01_000100_add_seo_og_to_venue_settings` (бэкфилл только пустых
колонок — правки владельца не затираются). Миграция накатана на сервере
деплоем — **ручных шагов не осталось**. Проверено живьём: `https://qmenu.kz/`
отдаёт нужные `<title>`, `description`, `keywords`, `og:*`.

## Горизонтальные ленты — таскаются мышью на ноутбуке (2026-09-01)

Промо-баннеры, лента «Рекомендуем» и вкладки категорий (все `overflow-x`
со скрытым скроллбаром `.no-scrollbar`) не листались обычной мышью на
ноутбуке — тач/трекпад листали нативно, а колесо и перетаскивание не
работали. Добавлена Alpine-директива **`x-drag-scroll`** (`resources/js/app.js`):
захват мышью (grab-drag) + колесо→горизонталь. **Только мышь** (`pointerType
=== 'mouse'`) — тач/трекпад оставлены на нативном скролле, иначе конфликт.
Драг дальше порога глотает последующий клик, чтобы карточки-ссылки в ленте
не открывались после перетаскивания. Директива навешена на 4 ленты в
`menu/home.blade.php`. Фронт-изменение → пересобрано `npm run build` +
`git add -f public/build`.

## Фото промо-баннеров — стоковые заглушки (2026-09-01)

Промо-баннеры показывали оранжевый градиент (`.promo-fallback`), т.к. у них
не было `image_path`. Команда **`php artisan demo:promo-photos`** (зеркало
`demo:dish-photos`) заливает стоковые фото LoremFlickr через `ImageOptimizer`
(WebP, 16:9-исходник). Идемпотентна; `--force` перезальёт. Ключуется по
`title_ru` (у промо нет слага). Прогнана на сервере — 3 баннера получили
фото (`storage/promos/*.webp`). Для реального заведения заменить своими через
админку. Запускать **вручную**, не в `deploy.sh`.

## Мобильные баги меню — отступы лент, подкатегории, хвост (2026-09-01)

Три правки после проверки на телефоне (`menu/home.blade.php`, `app.css`, `app.js`):

- **Боковые отступы промо/лент.** `.promo-scroll` и `.rail` больше не полагаются
  на `px-4` контейнера — часть мобильных движков **не рисует trailing inline-
  padding** у скролл-контейнера, и последняя карточка липла к краю. Отступы
  перенесены на **краевые дочерние элементы** (`> :first-child{margin-left}` /
  `> :last-child{margin-right}` в `app.css`) — margin у флекс-элементов рисуется
  всегда, оба края получают симметричный 1rem.
- **Подкатегории впритык к категориям.** Ряд чипов подкатегорий получил
  `pt-2` + верхнюю разделительную линию (`border-t border-border/60`), чтобы не
  сливался с рядом вкладок категорий над ним.
- **Большой хвост под последним блюдом.** Убран `min-h-[70vh]`-заполнитель;
  `setupScrollSpy()` теперь **подсвечивает последнюю вкладку у низа страницы**
  (`innerHeight + scrollY >= scrollHeight - 4`), поэтому короткой секции больше
  не нужна пустая площадь снизу. Нижний паддинг `<main>` ужат `pb-44` → `pb-32`.

Фронт-изменение → пересобрано `npm run build` + `git add -f public/build`,
задеплоено. Проверено живьём: новые бандлы `app-Bx34P4jY.js` / `app-CAfQ-u0U.css`
на `https://qmenu.kz/`, `min-h-[70vh]` в HTML отсутствует.

## Пустота под короткой категорией — прячем «обзор» + прижимаем к низу (2026-09-01)

При выборе **короткой** категории (напр. «Завтраки», 3 блюда) под последним
блюдом зияла большая пустая полоса до нижнего навбара. Причина: клик по вкладке
**пиннил** заголовок группы под липкую шапку, но контента группы (~443px) не
хватало заполнить область под шапкой (~574px) — оставшиеся ~131px = void.
С пиннингом эта дыра математически неизбежна для короткого контента.

Починка (`menu/home.blade.php` + `resources/js/app.js`):

- **Блоки «обзора» скрываются при фильтре.** «О заведении», сторис-промо и
  подборки-коллекции лежат в документе **над** липким `#menu-header`; они нужны
  только в общем виде «Все». Каждому добавлено `x-show="!searching && activeTop === 0"`
  — при выбранной категории сверху остаётся только cover-hero, без обрезков ленты.
- **Короткая группа прижимается к низу.** У обёртки группы появился
  `data-group="{{ $g->id }}"`. Переписан `selectTop(id)` в `app.js`: считает
  `pinTop` (заголовок под шапкой) и `bottomAlign` (низ группы над доком,
  `dockOffset: 72`), скроллит на `max(0, min(pinTop, bottomAlign))` — **высокая**
  группа пиннится как раньше, **короткая** прижимается к низу, так её блюда не
  висят над пустотой. `$nextTick` перед замером — чтобы `x-show` успел применить
  скрытие блоков обзора до расчёта высот.

Фронт-изменение → `npm run build` + `git add -f public/build`, задеплоено
(`68e6ae0`, бандл `app-Cj2x6SE9.js`). Проверено живьём Playwright (390×780):
«Завтраки» gap до навбара **131px → 13px**; «Кухня» (высокая) — заголовок
по-прежнему под шапкой (firstHeadingTop 188 ≈ headerBottom 180), скролл есть;
«Напитки» 13px; «Десерты» (2 блюда) — scrollY 0, полный cover-hero сверху, без
void. Регрессий нет.

⚠️ `goToSub` (клик по **подкатегории**) оставлен на пиннинге — редкий кейс
пустоты под самой последней короткой подкатегорией отложен.
