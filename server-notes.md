
## ⚠️ Сменить пароль root

Пароль сервера был передан в переписке и его стоит считать скомпрометированным.
Вход по ключу настроен, так что менять безопасно:

```bash
ssh root@185.194.217.14 "passwd"
```

Заодно можно вовсе отключить вход по паролю в `/etc/ssh/sshd_config`
(`PasswordAuthentication no`) — но только **после** проверки, что ключ работает,
иначе можно запереть себя снаружи.

## ⚠️ Кабинет по этому адресу работать не будет

API отдаётся по `http` на голом IP. Фронт на Vercel — по `https`. Отсюда:

- браузер **блокирует** запрос с https-страницы на http (mixed content);
- кука Sanctum на чужой домен требует `SameSite=None; Secure`.

Публичное меню при этом работает: оно без авторизации, и Next запрашивает его
на своей стороне, а не из браузера гостя.

Чинится только доменом:
```
qmenu.kz      → Vercel        (NEXT_PUBLIC_API_URL=https://api.qmenu.kz)
api.qmenu.kz  → этот сервер   (Certbot, SESSION_DOMAIN=.qmenu.kz)
```
У соседнего `api.phytobiotech.kz` Certbot уже настроен — схема отработана.

## ⚠️ Общий пул PHP-FPM

`systemctl reload php8.3-fpm` в `deploy.sh` перезапускает воркеры **всех**
проектов на сервере. Соседи не падают, но теряют прогретый opcache: первый
запрос после нашего деплоя у naryk шёл ~2 сек и один раз словил таймаут в
проверке. Так же делают деплои клиники и naryk — это принятая на этом сервере
практика.

Если понадобится изоляция — отдельный пул FPM на проект
(`/etc/php/8.3/fpm/pool.d/qr-menu.conf` со своим сокетом). Не делал: это
затрагивает общую конфигурацию, а её лучше менять осознанно.
